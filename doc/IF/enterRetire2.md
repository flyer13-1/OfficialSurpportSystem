# 概要

リタイア登録画面

# インターフェース仕様

リタイアした車両の情報を登録する

## API パス

- `/entries/retire`

## メソッド

- `POST`

## リクエスト

### クエリパラメータ

なし

### リクエストボディ

```json
{
  "carNum": 5,
  "reason": "エンジンブロー" // リタイア理由
}
```

- `carNum`: 車番（数値）
- `reason`: リタイア理由（文字列）。必須。空文字不可

## レスポンス

### ステータスコード

- `200 OK`: 正常なレスポンス（`msg`: 空文字）
- `400 Bad Request`: パラメータエラー（`msg`: エラー詳細）
- `401 Unauthorized`: 未ログイン（セッション切れ含む）（`msg`: エラー詳細）
- `403 Forbidden`: トークンが不正、または終了済みのレース（`reason: "race_finished"`）

**リタイア登録は担当エリアで制限しない（2026-10-09明記）。** 他の入力系API（`auto` / `hand` /
`update` / `start-driver`）は `findUnassignedCars` で担当エリア内の車両だけに絞り、
外なら 403「担当エリア外の車両です」を返すが、**この API だけは絞らない。**
リタイアは「見かけた車がコース上で止まった」ことを記録する操作で、自分の担当エリアの
車両に限らないため（[enterRetire.md](enterRetire.md) の `GET` も「担当エリアによるフィルタなし。
レースの全エントリー車両を返す」としている）。対象が当該レースの `entry` に存在するかは確認する（400）。

**既にリタイア登録されている車両は 409 で弾く（2026-10-09変更）。**

| 条件 | コード | msg |
| --- | --- | --- |
| 既にリタイア中（`is_retired: true`） | **409** | 「この車両は既にリタイア登録されています。理由の変更や取り消しは変更モードで行ってください」 |

- 以前は条件なしで `PutItem` していたため、**同じ車番を送ると理由が黙って上書きされ、先に入れた内容が消えていた。**
- 条件は「行が無いこと」ではなく「**リタイア中でないこと**」（`attribute_not_exists(car_num) OR is_retired = :false`）。取り消し（`PUT /entries/update` の `selection=3`）は行を消さずに `is_retired` を `false` にするため、**取り消した車両はもう一度リタイア登録できる**必要がある。
- 画面側も、取得済みの一覧（`GET /entries/retire` の `isRetired`）で登録済みの車番を持っておき、送る前に止める。
- **理由の訂正と取り消しは変更モード**（`PUT /entries/update` の `selection=2` / `3`。[enterUpdate2.md](enterUpdate2.md)）で行う。
- `500 Internal Server Error`: サーバーエラー（`msg`: エラー詳細）

### レスポンスボディ

```json
{
  "msg": "エラー内容"
}
```
