# 概要

登録画面の送受信

# インターフェース仕様

登録は3段階。

- ①checkUserを使って担当者名の重複確認　
- ②フロントが Cognito に直接 `signUp` → 確認コード入力で
  `confirmRegistration`（common.js の `cognitoPool` を使用）
- 確認後にこのAPIを呼び、アプリ側の UsersTable にユーザーを登録する。
  **パスワードはこのAPIには送らない**（Cognito側で保持・照合するため）。

## 画面の入力項目

画面（regist.html）では次の5項目をすべて必須で入力する。**このAPIに送るのはこのうち
担当者名とサーキットだけ**で、残りは Cognito 側に渡す。

| 入力項目           | 送り先                                    | 備考                                                                 |
| ------------------ | ----------------------------------------- | -------------------------------------------------------------------- |
| 担当者名           | このAPI（`username`）                     | ひらがな・カタカナ・漢字、3〜20文字                                  |
| **メールアドレス** | **Cognito の `signUp` の `Username`**     | **Cognito のサインイン設定が「Email のみ」のため、これがログインIDになる**（[index.md](index.md#ログインidはメールアドレス)）。`email` 属性としても渡す |
| パスワード         | Cognito の `signUp`                       | 強度規則は [common.md](common.md#パスワードの強度規則regist--forgetpass-の2画面) |
| 確認用パスワード   | どこにも送らない                          | 画面内の照合のみ。**一致するまで送信ボタンは無効**（下記）           |
| サーキット         | このAPI（`circuit`）                      | `select` で 1〜7 から選ぶ                                            |

**担当者名とメールアドレスは別物。** 担当者名は無線で呼ぶ名前としてアプリ側（UsersTable）が
持つ値で、Cognito には渡さない。逆にメールアドレスは Cognito だけが持ち、UsersTable には
保存しない。

## 入力検証（判定表）

この画面は2つの区画に分かれ、**区画ごとに送信ボタンと検証対象が切り替わる**
（仕組みは [common.md](common.md#6-入力検証の判定表) §6）。

| 区画          | 検証対象の欄                                              | 送信ボタン        |
| ------------- | --------------------------------------------------------- | ----------------- |
| `#formArea`   | パスワード（強度）／確認用パスワード（一致）              | アカウント登録    |
| `#codeArea`   | 確認コード（空でないこと）                                | 確認する          |

- **全欄が合格するまでボタンは押せない。** 一度も入力していない欄も不合格として扱う。
- **確認用パスワードは、パスワード本体を後から編集したときも再判定する。**
  一致させた後に本体を書き換えて不一致のまま送信する経路を塞ぐため。
- 「コードを再送信」は判定表の対象外（いつでも押せる）。
- 「確認する」は `type="button"` でブラウザの標準検証が働かないため、判定表が空入力を止める。

## リクエスト

### クエリパラメータ

なし

### リクエストボディ

担当者名はひらがな・カタカナ・漢字を有効化
**3-20文字以内**（当初は4文字以上としていたが、短い呼び名が使えず不便だったため
2026-10-05に3文字へ変更。フロント・`GET /user/check`・本APIの3箇所すべてで同じ規則）
サーキットは半角数字が下記のパターン入ります。
全部必須入力です

```json
{
  "username": "あそう太郎", // 担当者名
  "sub": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx", // Cognitoの signUp が返す userSub

  //１：富士　2：茂木　3：菅生　4:鈴鹿　5:岡山国際　6:その他　7:無所属
  "circuit": "1" //サーキット
}
```

## レスポンス

### ステータスコード

- `200 OK`: 正常なレスポンス
- `400 Bad Request`: パラメータエラー
- `500 Internal Server Error`: サーバーエラー

### レスポンスボディ

```json
{
  "msg": "エラー内容"
}
```
