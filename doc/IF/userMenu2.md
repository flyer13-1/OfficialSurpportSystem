## レスポンス

### ステータスコード

- `200 OK`: 正常なレスポンス（`msg`: 空文字）
- `401 Unauthorized`: 未ログイン（セッション切れ含む）（`msg`: エラー詳細）
- `403 Forbidden`: `users` に登録が無い（`msg`: 「ユーザーが見つかりません」、`reason`: `user_not_found`）
- `500 Internal Server Error`: サーバーエラー（`msg`: エラー詳細）

**400 は返さない（2026-10-07変更）。** このAPIはクエリパラメータもボディも取らないため、
パラメータエラーが起こり得ない。以前は「`users` に登録が無い」場合に 400 を返していたが、
01章§6 の403の表（`user_not_found`）に揃えて **403** に変更した。
管理者向けの `requireAdmin` は当初からこの形。

```json
{
  "msg": "ユーザーが見つかりません",
  "reason": "user_not_found",
  "username": "",
  "circuit": ""
}
```

フロントの `handleApiError` は 403 を「それ以外」の経路で `msg` を表示するだけなので、
**画面の挙動は 400 のときと変わらない**（遷移もしない）。

### レスポンスボディ

サーキット番号：１=富士、2=茂木、3=菅生、4=鈴鹿、5=岡山国際、6=その他、7=無所属

```json
{
  "msg": "",
  "username": "あそう太郎",
  "circuit": "1",
  "isAdmin": false
}
```

## フロントの扱い

- `circuit` は文字列で返る。フロント（conform）は sessionStorage の `circuit` に保存する。管理者画面は、`token` と `circuit` が sessionStorage に無ければ conform.html へ戻す（[admin/v2/01_permission.md](../aws-sam/admin/v2/01_permission.md) の §3・§7）。
- sessionStorage の `circuit` は画面のためだけのもの。管理者APIのサーキットの判定には使わず、サーバーが Users テーブルから調べる。
- `isAdmin` は、Cognito の `leader` グループ所属かどうか。「管理者画面へ」ボタンの表示に使う。
- 取得できた結果は画面内に保持し、再取得しない。leader を外されてもリロードまで反映されないが、これは許容する（[admin/v2/README.md](../aws-sam/admin/v2/README.md) の確定事項「leader 失効の遅れ」）。

### 取得の再試行（2026-10-07追加）

通信の瞬断やサーバーの一時的な失敗で画面が使えなくなるのを防ぐため、**最大3回まで取り直す**。

| 条件                        | 扱い                                                           |
| --------------------------- | -------------------------------------------------------------- |
| 通信エラー（fetch が失敗）  | 再試行の対象                                                   |
| `500` 番台                  | 再試行の対象                                                   |
| `401` / `403` / その他      | **再試行しない**（繰り返しても結果が変わらないため打ち切る）   |

- 試行の間隔は 500ms → 1000ms と空ける（続けて叩いても直らないことが多いため）。
- 3回とも失敗したら **「サーバーエラー：プロフィールを取得できません」** を表示する。
- **「プロフィール確認」ボタンを押したときにも取り直す。** 読み込み時に失敗していると
  ボタンを押しても何も起きない状態になっていたため（`prof()` が `loadProfile()` を待つ）。
