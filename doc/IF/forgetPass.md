# インターフェース仕様

**バックエンド API はない。** フロントエンドが Cognito User Pool に直接
パスワード再設定フロー（Forgot Password）を実行する（common.js の
`cognitoPool` を使用）。Cognito が確認コードを登録メールアドレス宛に送信するため、
現在のパスワードを知らなくても本人確認のうえ再設定できる
（旧仕様の「管理者が手動でリセット」運用は不要になった）。

## フロントエンドの処理（a_js/forgetPass.js）

### ステップ1: 確認コード送信

1. **メールアドレス**を入力する（担当者名ではない）
   - Cognito のサインイン設定が「Email のみ」のため、`CognitoUser` に渡す `Username` も
     メールアドレスになる（[index.md](index.md#ログインidはメールアドレス)）
   - 画面の入力欄は `<input type="email" id="username">`（id は `username` だが中身はメールアドレス）
2. `CognitoUser.forgotPassword()` を呼ぶ → 登録メールアドレスに確認コードが届く
3. 成功時: コード入力画面（codeArea）へ切り替え

### ステップ2: 確認コード + 新パスワードで再設定

1. 確認コード・新しいパスワード・確認用パスワードを入力する
   - パスワードの強度規則は
     [common.md](common.md#パスワードの強度規則regist--forgetpass-の2画面)。
     6〜20文字・大文字・小文字・数字を各1文字以上・半角英数字のみ
   - **3つすべてが合格するまで「パスワードを再設定」は押せない**（下記）
2. `CognitoUser.confirmPassword(code, newPassword)` を呼ぶ
3. 成功時: 完了メッセージを表示しログイン画面（index.html）へ遷移
4. 失敗時（コード不一致・期限切れ等）: エラーメッセージを表示。「コードを再送信」で
   `forgotPassword()` を再度呼べる

## 入力検証（判定表）

この画面は2つの区画に分かれる（仕組みは [common.md](common.md#6-入力検証の判定表) §6）。

| 区画          | 検証対象の欄                                                             | 送信ボタン            |
| ------------- | ------------------------------------------------------------------------ | --------------------- |
| `#formArea`   | なし（`required` / `type="email"` の標準検証に任せる）                   | 確認コードを送信      |
| `#codeArea`   | 確認コード（空でない）／新パスワード（強度）／確認用（一致）             | パスワードを再設定    |

**「パスワードを再設定」は `type="button"` のため、ブラウザの標準検証
（`required` / `minlength`）が一切働かない。** フォーム送信ではないため、
`<input>` に付けた属性は評価されない。判定表が3欄すべての合格を要求することで、
**確認用が空のまま再設定されるのを防いでいる**（2026-10-06 修正）。

- 「コードを再送信」は判定表の対象外（いつでも押せる）。

## バックエンド側の変更

- `POST /user/password` Lambda（changePassword.mjs）は**廃止**。
