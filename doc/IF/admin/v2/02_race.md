# 02 race（項目・登録・確認の表示・変更・終了後の表示）

状態: **ドラフト（レビュー待ち）**

race の項目と、管理者画面での登録・一覧・変更、終了後の見え方を、フロントとバックエンドを合わせて定める。権限とエラーの共通ルールは [01_permission.md](01_permission.md)（確定）に従う。

race に属するデータ（entry / start_driver / pit_assignment）と race の削除は03章、pitlog の参照・ダウンロードは04章で扱う。

## 1. 項目

| 項目（body）     | DB列              | 型                  | 入力     | 説明                                                                                                                                                                                                                                              |
| ---------------- | ----------------- | ------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `raceId`         | `id`（PK）        | 文字列              | **自動** | システム内部のキー。**予測不可能な値**にし、**全サーキットを通して一意**とする（§2.3）。一般向けAPIは、この予測不可能性を安全装置として `race_id` を信用する（01章 R9）。管理者が一覧で参照したい場合は、行番号（保存しない・表示専用）で代替する |
| `title`          | `title`           | 文字列              | 入力     | レースタイトル。1〜200文字。前後の空白は除く。**同じサーキットの中で重複不可**（R8）                                                                                                                                                              |
| `todayId`        | `today_id`        | 文字列              | **自動** | 当日配布する大会ID。conform の入室に使う。全サーキットで一意（§2.3）                                                                                                                                                                              |
| `organizationId` | `organization_id` | 数値                | **自動** | 所属サーキット。登録した管理者のサーキットをサーバーが付ける。変更不可                                                                                                                                                                            |
| `finishDate`     | `finish_date`     | 文字列 `YYYY-MM-DD` | 入力     | レース終了日（JST の日付）。この日の翌日 0:00（JST）以降が終了済み（01章 §1）。DynamoDB に日付型が無いため文字列で保存する                                                                                                                        |
| `createdAt`      | `created_at`      | 文字列（ISO 8601）  | 自動     | 登録日時。ログの観点から保持する                                                                                                                                                                                                                  |
| `createdBy`      | `created_by`      | 文字列              | 自動     | 登録した管理者の `sub`。ログの観点から保持する                                                                                                                                                                                                    |

- `raceId` / `todayId` / `organizationId` は、リクエスト body に含まれていても無視する（01章 §5.1）。
- `circuit` の型: `GET /user/me` は文字列で返し、`users.organization_id` と `race.organization_id` は数値。サーバー内の比較は数値に統一する。

### キーと索引

| 索引                        | キー                                                               | 用途                                                                      |
| --------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| （テーブル本体）            | PK `id`                                                            | `raceId` での取得・更新                                                   |
| `OrganizationIndex`（新規） | HASH `organization_id` ／ RANGE `finish_date`。Projection: **ALL** | 自分のサーキットの一覧（終了日順）と、同一サーキット内の title 重複の確認 |
| `TodayIdIndex`（新規）      | HASH `today_id`                                                    | conform の大会ID照合と、`todayId` の重複確認（今の全件 Scan をやめる）    |

## 2. 登録

### 2.1 画面

入力欄は次の3つ。

| 欄             | 内容                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------- |
| レースタイトル | 必須                                                                                            |
| 終了日         | 必須。日付の入力欄。今日（JST）より前は選べないようにする（見た目のためだけで、判定はサーバー） |
| サーキット     | 表示のみ。自分のサーキット名を出す。送信はしない                                                |

`raceId` と `todayId` の入力欄は置かない。

登録の流れは次のとおり。

1. **確認:** 「確認」を押すと、ポップアップに**入力した内容だけ**（タイトル・サーキット・終了日）を表示する。「大会IDは登録後に表示されます」と添える。「戻る」「登録する」を置く。
2. **完了:** 登録に成功したら、ポップアップに **大会ID（`todayId`）を1回表示**し、コピーボタンを付ける。当日に配る値であることを添える。
3. 閉じたあとは、一覧に反映する。大会IDは、一覧の「表示」から見直せる（§3）。

`todayId` は登録時にサーバーが作るため、登録前の確認では見せられない。`raceId` は画面に表示しない（内部のキーであり、管理者が手で使う場面が無いため。01章参照）。

### 2.2 API: `POST /race`

リクエスト:

```json
{
  "title": "2026 AUTOBACS SUPER GT Round4 FUJI GT 300km RACE",
  "finishDate": "2026-08-30"
}
```

処理の順序:

1. `requireAdmin`（01章 §4）
2. 入力の検証（下表）
3. 同じサーキットに同じ `title` があれば 409（`OrganizationIndex` を引く）
4. `todayId` を作り、`TodayIdIndex` で重複を確認する（重複したら作り直し。最大10回）
5. `raceId` を作り、`attribute_not_exists(id)` 付きで保存する（重複したら作り直し。最大3回）
6. 成功を返す

レスポンス（200）:

```json
{
  "msg": "",
  "todayId": "K7mPq3TnW2vXzR8sH"
}
```

- `raceId` は返さない。登録後、画面は `GET /race`（一覧）を呼び直すため、`raceId` はそちらから手に入る。完了ポップアップで人が読む必要があるのは `todayId` だけ。
- `todayId` は、この応答と、一覧の「表示」でだけ見える。旧設計書では「既定では返さない」としていたが、完了画面で見せるために返す。呼べるのは自分のサーキットの管理者だけ（01章）。

エラー:

| 条件                                | コード    | msg                                              |
| ----------------------------------- | --------- | ------------------------------------------------ |
| `title` が空、または200文字を超える | 400       | 「レースタイトルは1〜200文字で入力してください」 |
| `finishDate` が日付の形式でない     | 400       | 「終了日を正しい形式で入力してください」         |
| `finishDate` が今日（JST）より前    | 400       | 「終了日は今日以降の日付を指定してください」     |
| 同じサーキットに同名の race がある  | 409       | 「同名のレースが既に登録されています」           |
| `raceId` / `todayId` を作れなかった | 500       | 「サーバーエラーが発生しました」                 |
| 権限・認証                          | 401 / 403 | 01章 §6                                          |

一括登録（`/race/bulk`）は作らない。1件ずつ登録する。

### 2.3 `raceId` と `todayId` の生成

|                | `raceId`                                                         | `todayId`                                                                      |
| -------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 生成場所       | サーバー（Lambda）                                               | サーバー（Lambda）                                                             |
| 乱数           | 暗号論的な乱数（`crypto`）。`Math.random` は使わない             | 同左                                                                           |
| 形             | 16バイトの乱数を URL 安全な Base64 にした22文字（`A-Za-z0-9_-`） | 17文字。紛らわしい文字（`0`/`O`、`1`/`l`/`I`）を除いた英数字                   |
| タイトルの流用 | しない                                                           | **しない**（今の実装は先頭にタイトルの文字が入り、推測の手がかりになる）       |
| 一意の保証     | 保存時の条件付き書き込み                                         | `TodayIdIndex` での確認                                                        |
| 使う場所       | 各APIの `race_id`                                                | conform の大会ID入力（手で打つ。既存の形式 `^[A-Za-z0-9\-_!]{15,}$` を満たす） |

## 3. 一覧: `GET /race`

自分のサーキットの race を、終了済みも含めて返す（01章 §5.1）。

```json
{
  "msg": "",
  "races": [
    {
      "raceId": "kQ3v9Zp2mT8xLw1nYb7RcA",
      "title": "2026 ... FUJI GT 300km RACE",
      "finishDate": "2026-08-30",
      "status": "active",
      "todayId": "K7mPq3TnW2vXzR8sH"
    }
  ]
}
```

| `status`   | 意味                   | `todayId`    |
| ---------- | ---------------------- | ------------ |
| `active`   | 開催中（終了日より前） | 返す         |
| `lastDay`  | 本日が終了日           | 返す         |
| `finished` | 終了済み               | **返さない** |

- `status` は DynamoDB には保存しない。`GET /race` が呼ばれるたびに、Lambda が `finish_date` と現在時刻（JSTに直したもの）を比べてその場で計算する（01章 §5.3）。事前に計算して保存する方式だと、日付が変わる瞬間に書き換えるバッチ処理が別途必要になり、失敗・遅延でズレる恐れがあるため採らない。画面はクライアントの時計で判定しない。
- 0件のときは `races: []`。

### 表示

| 項目         | 内容                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 列           | タイトル、大会ID+[表示ボタン]、終了日、状態、操作                                                                                   |
| 大会ID       | 普段は伏せておき、行の「表示」を押すと見える（当日に配る値のため、管理者は見られるようにする）                                      |
| 並び順       | 開催中（`active` / `lastDay`）を上、終了済みを下。それぞれ終了日の新しい順（API が終了日の新しい順で返すものを、画面で2つに分ける） |
| 検索・ソート | 今は作らない（将来の機能として検討）                                                                                                |

## 4. 変更

### 4.1 変更できる項目

`title` と `finishDate` だけ。`raceId`・`todayId`・サーキットは変更できない。終了済みの race は変更できない（01章 R7）。

### 4.2 画面

1. 行の「変更」を押すと、ポップアップに現在の値が入った `title` と `finishDate` を出す。`raceId`・サーキットは表示のみ。
2. 「確認」を押すと、**変更した項目だけ**を「変更前 → 変更後」で表示する。変更が無ければ、確認に進めない。
3. 「保存する」で送信する。
4. 今の `prompt()` による入力はやめる。

### 4.3 API: `PUT /race`

```json
{
  "raceId": "kQ3v9Zp2mT8xLw1nYb7RcA",
  "title": "2026 ... FUJI GT 300km RACE (改)",
  "finishDate": "2026-08-31"
}
```

処理の順序:

1. `requireAdmin`
2. race を取得する。存在しない、または他サーキット → 404（01章 §5.1）
3. 終了済みなら 403（`reason: "race_finished"`）
4. 入力の検証（登録と同じ。`finishDate` は今日（JST）以降）
5. `title` を変える場合は、同じサーキットの他の race との重複を確認する（409）
6. 更新して `{ "msg": "" }` を返す

- 終了日は、短くしても延ばしてもよいが、今日（JST）より前にはできない（変更で終了済みにできない）。
- `todayId` の再発行は、今は作らない。

## 5. 終了後の表示（一覧）

| 状態     | 行の見た目                 | 変更     | pitlog（04章。参照＋ダウンロードの両方） | 大会ID     |
| -------- | -------------------------- | -------- | ---------------------------------------- | ---------- |
| 開催中   | 通常                       | 使える   | 使える                                   | 見られる   |
| 本日終了 | 通常（開催中と同じ。特別な印は付けない） | 使える   | 使える                                   | 見られる   |
| 終了済み | 薄い表示＋「終了済み」の印 | **無効** | **使える（参照・ダウンロードとも）**     | 見られない |

`status`（`active` / `lastDay` / `finished`）はAPIレスポンスとしては3値のまま返す（大会IDを返すかどうかの判定に使うため）。見た目上は `active` と `lastDay` を区別しない。

- 無効にするのは見た目だけで、判定はサーバー（403）。
- 削除ボタンの扱いは、配下データとの関係があるため03章で決める。

### 決定済み（参考）

- `createdAt` / `createdBy` は持つ。ログの観点から保持する。
- 開催日（開始日）は持たない。`finish_date` は操作をロックする目的（01章 R7・終了判定）のためだけに使うため、`finish_date` だけで足りる。
- `OrganizationIndex` の RANGE は `finish_date` のままとする。文字列 `YYYY-MM-DD` は大小比較がそのまま日付順になるため、追加コストなしで終了日順の一覧が得られる（§1 参照）。
- 一覧の並び順は §3 に記載のとおり（開催中を上・終了済みを下、それぞれ終了日の新しい順）で変更しない。
- 「本日終了」の特別な印は付けない。`status` はAPIレスポンスとしては3値のまま返すが、見た目は開催中と同じにする（§5）。
