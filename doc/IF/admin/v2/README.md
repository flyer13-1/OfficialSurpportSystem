## 02章に引き継ぐこと

- race の列名は SQLcode.sql に合わせて `organization_id` / `finish_date`（DynamoDB 側はまだ未定義）
- `raceId` の生成: 予測不可能（暗号論的な乱数）・全体で一意にする。現状の admin 画面は管理者が手で入力しており、旧設計書も手動採番としているため、自動生成に変える。生成の場所（サーバーか、画面の JS か）は02章で決める。既存の race（例 `2026test_race`）は推測しやすいので、作り直しか移行が必要
- `circuit` の型: `GET /user/me` は文字列で返し、`users.organization_id` と `race.organization_id` は数値。サーバー内の比較は数値に統一する

## 03章・04章に引き継ぐこと

- 03章: 管理者向けの pitlog 参照API。`showAll.mjs` のデータ生成を共通の関数に切り出し、一般向け（終了済みは 403）と管理者向け（`requireAdmin` ＋ race の照合）の2つのハンドラから使う
- 04章: pitlog を表示するポップアップとダウンロードボタン。`showAll.js` / `showAllGimic.js` の表示処理を流用する際は、`entries` などのグローバル名が `admin.js` と衝突しないようにする
