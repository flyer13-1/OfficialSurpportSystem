# 概要

確認画面からメイン画面に遷移する

> **画面の区画について（2026-10-06）**
> `conform.html` は3つの区画（`#formArea` 大会ID入力 / `#conform` プロフィール /
> `#msgArea` 承認メッセージ）を切り替えて使う。切り替えは `common.js` の `showStep()`、
> 成功後の遷移は `finishTo()` が担う（[common.md](common.md#7-区画切り替え-showstep)）。
> **2番目の区画名は他画面と違い `#codeArea` ではなく `#conform`。**
> この画面のAPI・処理フローそのものの照合はまだ行っていない（②conform で実施予定）。

# インターフェース仕様

送られた大会IDが正しければメイン画面に遷移する

## API パス

- `/user/me`

## メソッド

- `POST`

## リクエスト

### クエリパラメータ

なし

### リクエストボディ

大会IDは半角英数の大文字小文字・１５文字以上
全部必須入力です

```json
{
  "todayId": "2026xcde554" // 大会ID
}
```

## レスポンス

### ステータスコード

- `200 OK`: 正常なレスポンス（`msg`: 空文字、`raceId` を返す）
- `400 Bad Request`: パラメータエラー、大会IDが一致しない（`msg`: エラー詳細）
- `401 Unauthorized`: 未ログイン（セッション切れ含む）（`msg`: エラー詳細）
- `403 Forbidden`: 終了済みのレース（`msg`: 「終了したレースです」、`reason`: `race_finished`）
- `500 Internal Server Error`: サーバーエラー（`msg`: エラー詳細）

### レスポンスボディ

正常時:

```json
{
  "msg": "",
  "raceToken": "eyJyYWNlSWQiOi...7f2a9c4e..." // 以降のAPIに渡す。フロントは sessionStorage に保存する
}
```

- `raceId` はもう返さない。署名付きの `raceToken` を返し、以降は常に `X-Race-Id` ヘッダーで送る（[raceIdToken.md](raceIdToken.md) §3・§4、01章 R10）。

エラー時:

```json
{
  "msg": "エラー内容"
}
```

終了済みのレース（403）:

```json
{
  "msg": "終了したレースです",
  "reason": "race_finished"
}
```

## 終了済みのレースについて

- `race.finish_date` の翌日 0:00（JST）以降のレースは終了済みとして、大会IDが一致しても入室できない（`403`）。
- 大会IDでの入室は、利用者のサーキットでは制限しない（他サーキットからの応援があるため）。
- フロント（conform）は、`403` を受けたら `msg` を表示して確認画面にとどまる。画面は移動しない。
- 判定の詳細は [admin/v2/01_permission.md](../aws-sam/admin/v2/01_permission.md) の §5 を参照。

## 終了日が無いレースについて（2026-10-07追加）

`finish_date` は02章§2でレース登録時の必須項目のため、**本来この状態は起こらない。**
データの欠損や改ざんで消えた場合の安全策として、次の扱いにする。

| 項目               | 扱い                                                                      |
| ------------------ | ------------------------------------------------------------------------- |
| 終了済みの判定     | 判定できないため行わない（入室は許す）                                    |
| トークンの有効期限 | **現在時刻 + 2時間**（[raceIdToken.md](raceIdToken.md) §7）               |
| 超過後             | `exp` 切れとして一般向けAPIが **403**（`reason: race_finished`）を返す     |
| レスポンス         | `200` のまま。`warning: "finish_date_missing"` を足す                     |
| 画面              | その場で**管理者への連絡を促すメッセージ**を出し、そのうえでメイン画面へ進む |

```json
{
  "msg": "",
  "raceToken": "eyJyYWNlSWQiOi...7f2a9c4e...",
  "warning": "finish_date_missing"
}
```

- **`msg` は空文字のままにする。** フロントの `handleApiError` は非空の `msg` をエラーとして
  扱い処理を打ち切るため、警告を `msg` に入れると入室できなくなる（[common.md](common.md#handleapierrorresponse-data)）。
- 画面の文言: 「このレースには終了日が設定されていません。利用できるのは2時間だけです。
  至急、管理者に連絡してください。」
- サーバー側は `console.warn` でログに残す（`raceId` と `todayId`）。調査できるようにするため。
- **2時間にした理由:** 期限の無いトークンを出さないことを優先する。作業を続けられる長さは
  確保しつつ、放置された異常なレースが一日中使える状態にはしない。超過したら conform を
  やり直すことになるが、その時点で管理者が `finish_date` を直しているのが期待される流れ。
